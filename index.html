Setup Guide — Hosting on GitHub + Supabase

Step 1 — Create a Supabase Project (Free)

  1. Go to supabase.com and sign up for a free account
  2. Click New Project, give it a name (e.g. "gls-invoices"), choose Singapore region
  3. Set a database password and wait for it to provision (~2 minutes)

Step 2 — Create the Invoices Table

In your Supabase project, go to SQL Editor and run this query:

CREATE TABLE invoices (
  id          uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  created_at  timestamptz DEFAULT now(),
  inv_no      text NOT NULL,
  inv_date    date NOT NULL,
  period      text,
  gross       numeric(12,2),
  net_sales   numeric(12,2),
  commission  numeric(12,2),
  cgst        numeric(12,2),
  sgst        numeric(12,2),
  total       numeric(12,2),
  net_remit   numeric(12,2),
  metadata    jsonb
);

-- Allow public read/write (for anon key access)
ALTER TABLE invoices ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Allow all" ON invoices FOR ALL USING (true) WITH CHECK (true);

Step 3 — Get Your API Keys

  1. In Supabase, go to Settings → API
  2. Copy the Project URL (looks like https://xxxx.supabase.co)
  3. Copy the anon public key (the long JWT string)
  4. Paste both in the sidebar under Database (Supabase) and click Save & Test Connection

Step 4 — Host on GitHub Pages (Free)

  1. Create a free account at github.com
  2. Create a new repository — name it anything (e.g. "gls-invoice-generator")
  3. Upload this index.html file to the repository
  4. Go to Settings → Pages in the repository
  5. Under Source, select Deploy from a branch → main → / (root)
  6. Click Save. Your app will be live at https://yourusername.github.io/gls-invoice-generator in ~2 minutes

Step 5 — First Use

  1. Open the app in your browser
  2. Click ⚙ Configure Supabase connection in the sidebar and enter your URL and key
  3. Enter gross collections, adjust the invoice details, and click Save Invoice
  4. View all past invoices under the Past Invoices tab
Security note: Your Supabase keys are stored in your browser's localStorage — they never leave your device. The anon key is designed for browser use and is safe to use this way. For production use, consider adding authentication to your Supabase project.
